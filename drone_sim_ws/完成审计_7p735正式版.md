## 控制解耦和物理耦合

键盘和飞行控制只通过ROS 2 DDS发布PX4 Offboard消息；机械臂只通过 `/arm_controller/joint_trajectory` 控制。两者通道解耦，但Gazebo中机械臂仍是同一浮动多刚体，运动会改变COM、惯量并产生反作用力/扰动力矩，直接动力插件按八个CAD电机轴对机体施力。

## 已知卡点及边界

完整 `work_a/work_b` 在3秒内展开的实测会使电机饱和，水平漂移约4.6–6.1 m；将完整 `work_a` 放慢到30秒的诊断仍出现饱和/failsafe。这不是测试脚本忽略，而是7.735 kg仅约7.5%理想推力余量下的真实失稳结果。当前飞行联合测试采用约20%幅度的 `flight_work_a/flight_work_b` 和8秒渐进轨迹。完整动作仍可在地面运行。

以下仍需外部实测后才能称为实机标定：桨叶真实螺距正负、每台电机RPM—推力—扭矩、电机时间常数、ESC延迟、电池内阻/电压、空气阻力/地效、最终整机称重和惯量。4/5/7/8相反螺距是当前悬停可行性假设，不是平板桨CAD的直接证据。

## 重新生成和安装

```bash
cd '/mnt/e/清洁无人机/drone_sim_ws'
export PYTHONPATH=src/drone_arm_sim
python3 src/drone_arm_sim/scripts/build_7p735_flight_config.py
python3 src/drone_arm_sim/scripts/generate_cad_px4_airframe.py \
  --config src/drone_arm_sim/config/my_drone_v3_cad_7p735_flight.json \
  --output px4/airframes/4026_gz_my_drone_octorotor_7p735
bash scripts/wsl_install_px4_airframe.sh 4026_gz_my_drone_octorotor_7p735
```

若WSL环境把 Windows Miniforge 放进CMake搜索路径，先使用纯Linux PATH重建PX4；否则会出现 `protoc` 版本和Gazebo protobuf头文件不匹配。
