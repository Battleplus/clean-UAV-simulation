# my_drone Gazebo＋PX4＋ROS 2 DDS 启动说明

适用环境：默认 WSL `Ubuntu-24.04`、ROS 2 Jazzy。

> 当前稳定版本：PX4 飞行控制、ROS 2 DDS、WASD 与机械臂 `ros2_control` 已打通。
> PX4 负责飞行，机械臂使用独立关节控制器；二者控制通道解耦，Gazebo 中仍保留
> 机械臂运动产生的重心变化和刚体反作用。

```text
Windows 项目：E:\清洁无人机\drone_sim_ws
WSL 项目：/mnt/e/清洁无人机/drone_sim_ws
PX4：/home/asus/PX4-Autopilot
```

推荐链路：

```text
键盘 WASD → ROS 2 Offboard节点 → Micro XRCE-DDS → PX4 SITL
          → PX4执行器 → Gazebo动力模型 → Gazebo/ROS 2状态反馈
```

不要同时运行旧的 `px4_wasd_control.py` 或其他 pymavlink Offboard 程序，否则会产生指令竞争。

## 0. 最短启动清单

1. 在第一个 PowerShell 窗口启动后端，等待出现 `ROS2_DDS_READY arm_control=true`。
2. 保持 Gazebo 窗口开启，在第二个 PowerShell 窗口启动 WASD 控制器。
3. 点击 WASD 控制终端，使其获得键盘焦点。
4. 等待预检通过后按 `T` 起飞；用 `W/S/A/D/R/F/Q/E` 控制。
5. 结束时按 `L`，确认落地并自动上锁后再关闭窗口。

不要在飞机仍解锁或飞行时直接关闭 PX4、Gazebo 或控制终端。

## 1. 正常启动

打开两个 PowerShell 窗口。

### 窗口一：启动 Gazebo、PX4 和 DDS

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "cd '/mnt/e/清洁无人机/drone_sim_ws' && HEADLESS=false bash scripts/wsl_start_ros2_dds.sh"
```

脚本将依次启动：

1. Micro XRCE-DDS Agent（UDP `8888`）；
2. Gazebo `flight_world` 和 `my_drone`；
3. PX4 SITL，机型编号 `4025`；
4. 等待 PX4 ROS 2 DDS 话题出现。

出现以下内容表示后端就绪：

```text
ROS2_DDS_READY arm_control=true
logs=/tmp/my_drone_ros2_dds
```

如只验证飞行、不启动机械臂控制器，可使用兼容入口：

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "cd '/mnt/e/清洁无人机/drone_sim_ws' && HEADLESS=false bash scripts/wsl_start_ros2_dds_noarm.sh"
```

首次启动可能需要数十秒。未出现就绪标志时不要启动飞行操作，按本文第 7、8 节检查日志。

如果以 `HEADLESS=true` 启动，之后可单独补开 Gazebo GUI：

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "source /opt/ros/jazzy/setup.bash && gz sim -g --force-version 8"
```

### 窗口二：启动 WASD 控制器

```powershell
powershell -ExecutionPolicy Bypass -File "E:\清洁无人机\drone_sim_ws\scripts\start_ros2_dds_wasd.ps1"
```

弹出的 WSL 终端必须保持打开并获得键盘焦点。控制输入不会发送到 Gazebo 主窗口。

如果还需要同时连接一个 Gazebo GUI：

```powershell
powershell -ExecutionPolicy Bypass -File "E:\清洁无人机\drone_sim_ws\scripts\start_ros2_dds_wasd.ps1" -AttachGazeboGui
```

也可以直接在 WSL 中运行：

```bash
cd '/mnt/e/清洁无人机/drone_sim_ws'
bash scripts/run_ros2_dds_wasd.sh
```

## 2. 键盘控制

必须让 WASD 终端保持焦点。

| 按键 | 功能 |
|---|---|
| `T` | 预发送 Offboard 目标，随后解锁并起飞至约 1.2 m |
| `W` / `S` | 沿当前机头方向前进／后退 |
| `A` / `D` | 向机体左侧／右侧移动 |
| `R` / `F` | 上升／下降 |
| `Q` / `E` | 向左／向右偏航 |
| `L` | 自动降落，落地后自动上锁 |
| `O` | 退出 Offboard 并请求 POSCTL |
| 连按两次 `X` | 紧急强制上锁，仅在失控时使用 |
| `Z` | 未解锁时安全退出；已解锁时先请求降落 |

推荐顺序：

```text
等待 preflight checks 通过 → T → 稳定悬停
→ W/S/A/D/R/F/Q/E → L → LANDING_DISARMED_CONFIRMED
```

## 3. 机械臂控制

后端必须使用 `wsl_start_ros2_dds.sh` 启动。另开 PowerShell 窗口执行：

```powershell
# 展开到工作姿态 A
wsl.exe -d Ubuntu-24.04 -- bash "/mnt/e/清洁无人机/drone_sim_ws/scripts/run_ros2_arm_preset.sh" work_a 3

# 切换到工作姿态 B
wsl.exe -d Ubuntu-24.04 -- bash "/mnt/e/清洁无人机/drone_sim_ws/scripts/run_ros2_arm_preset.sh" work_b 3

# 收回机械臂
wsl.exe -d Ubuntu-24.04 -- bash "/mnt/e/清洁无人机/drone_sim_ws/scripts/run_ros2_arm_preset.sh" retracted 3
```

最后一个参数是动作时长，单位秒。命令成功时会显示 `ARM_PRESET_REACHED` 和最大关节误差。
机械臂可在落地或悬停时操作；首次操作建议先在落地未解锁状态验证。

## 5. 自动飞行回归测试

以下测试会真实执行仿真解锁、起飞、W/D/S/A 和降落。先确认没有连接实机，并且没有其他控制器运行：

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "cd '/mnt/e/清洁无人机/drone_sim_ws'; source /opt/ros/jazzy/setup.bash; source /home/asus/ros2_px4_build_ws/install/setup.bash; source install/setup.bash; python3 scripts/test_ros2_dds_wasd_pty.py"
```

通过标志：

```text
DDS_WASD_PTY_PASS
```

飞行中机械臂动作联合测试：

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "source /opt/ros/jazzy/setup.bash; source /home/asus/ros2_px4_build_ws/install/setup.bash; source '/mnt/e/清洁无人机/drone_sim_ws/install/setup.bash'; cd '/mnt/e/清洁无人机/drone_sim_ws'; python3 scripts/test_ros2_dds_arm_flight_pty.py"
```

通过标志为 `DDS_ARM_FLIGHT_PASS`。最近一次实测机械臂动作期间最大水平漂移为
`0.104 m`，高度波动范围为 `0.028 m`，三种姿态均到达，随后正常降落上锁。

## 6. 正常关闭与异常清理

正常情况下先按 `L`，等待落地并自动上锁，再关闭窗口。

若上一次异常退出，重新启动前清理本项目仿真进程：

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "pkill -x gazebo_direct_m || true; pkill -x parameter_bridg || true; pkill -x robot_state_pub || true; pkill -x ros2 || true; pkill -x px4 || true; pkill -x MicroXRCEAgent || true; pkill -x ruby || true"
```

检查是否仍有残留：

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "ps aux | grep -E 'px4|MicroXRCE|gz sim|dds_wasd' | grep -v grep || true"
```

正常情况下只能有一个 `gazebo_direct_motor_model` 和一个 `parameter_bridge`。多个动力节点会重复发布 wrench，多个桥会把同一条 ROS wrench 多次转发给 Gazebo，两种情况都会使受力倍增并导致飞行立即发散。新版启动脚本默认先清理旧仿真进程；只有显式设置 `CLEAN_STALE_RUNTIME=0` 才会跳过清理。

## 8. 常见问题

### Gazebo 中看不到飞机

在 Gazebo 实体树中选中 `my_drone`，按 `F` 聚焦。若实体树不存在 `my_drone`，检查 `gazebo.log` 中的 URDF、网格和 spawn 错误。

### DDS 话题没有出现

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "ss -lunp | grep 8888 || true; tail -n 80 /tmp/my_drone_ros2_dds/agent.log; tail -n 80 /tmp/my_drone_ros2_dds/px4.log"
```

### 无法解锁

不要反复按 `T`。检查：

- `pre_flight_checks_pass`；
- `failsafe`；
- `VehicleCommandAck result`；
- `px4.log` 中的 preflight failure 原因。

### 新推力模型下悬停不稳

Gazebo 已使用用户提供的 14.8 V 静态推力曲线和 `0.035 s` 初始电机时间常数。它与旧线性模型不同，需要重新校准 `MPC_THR_HOVER`，必要时调整姿态和位置增益。

### 控制终端显示 `motors=absent`

ROS 2 节点和本地 PX4 已加入 `/fmu/out/actuator_outputs` 发布/订阅，并完成不解锁实测。正常待机应显示八路 `0.00`，起飞后显示实时输出。如果仍为 `absent`，通常是启动了旧 PX4 二进制、Agent 未连接，或 ROS 2 环境没有加载本项目安装空间。

## 9. 当前模型边界

- 工作飞行模型约 `4.184 kg`，用于验证 PX4、DDS 和 WASD 功能。
- CAD 密度估算正式模型约 `8.567 kg`。
- 额定 `1.2 kgf/电机` 下，8.567 kg 模型最大垂直推重比约 `0.97`，不能稳定起飞。
- CAD 中简化桨叶无法可靠识别螺距正负，正式推力符号仍需桨叶型号、左右旋标识或更精细 CAD。
- `0.035 s` 电机时间常数是初始估值，不是实测阶跃响应。
- 当前反扭矩采用 `Q/T=0.001 m` 经验估算，并已通过单桥完整飞行回归；它仍需真实 `C_Q/C_T` 或 RPM—扭矩数据校准。
- IMU、磁力计和气压计噪声采用 PX4 官方 Gazebo x500 模型的量级，使 PX4 DataValidator 能正确区分有效传感器与停更数据。
- 当前启动入口使用 `my_drone_v2_cad_flight_pitch_corrected.json` 和 PX4 机型 `4025`。
- 机械臂位置控制已通过 `gz_ros2_control` 接入；当前使用 CAD 关节轴与关节中心、位置接口和三组预设姿态。
