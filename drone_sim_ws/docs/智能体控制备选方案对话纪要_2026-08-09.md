# 智能体控制备选方案对话纪要

日期：2026-08-09
项目：`my_drone` 7.735 kg 八旋翼＋SO101 机械臂 Gazebo/PX4 仿真

## 1. 当前冻结决定

现阶段继续以 **WASD 人工飞行控制为主**，优先把以下链路稳定调通：

```text
键盘 WASD → ROS 2 DDS Offboard 控制 → PX4 SITL → Gazebo 正式 CAD 模型
```

智能体控制暂时不进入正式启动链路，不替代 WASD，不自动接管飞行、机械臂或
PX4 LAND。智能体方案作为后续备选研究方向保存。

本决定的原因：

1. 前后左右、升降和偏航等即时操作，WASD 响应更快、行为更直接；
2. 如果智能体仅把按键翻译成位置增量，会增加延时和故障点，没有实际收益；
3. 当前更重要的是验证正式 CAD 八旋翼的控制方向、悬停稳定性、降落和人工接管；
4. 自然语言模型不应进入 PX4 的实时控制回路；
5. 机械臂完整飞行动作和负载飞行仍需进一步校准，应先保留简单、可验证的控制链。

## 2. WASD 与智能体的边界

### WASD 适用范围

- 仿真调试和方向确认；
- 近距离人工调整；
- 前后左右、升降、偏航和降落；
- 发生异常时人工接管；
- 低延时、可预测的单步操作。

当前正式按键为：

| 按键 | 功能 |
|---|---|
| `T` | 进入 Offboard、解锁并起飞 |
| `W/S` | 前进/后退 |
| `A/D` | 左移/右移 |
| `R/F` | 上升/下降 |
| `Q/E` | 左转/右转 |
| `L` | 自动降落并解除武装 |
| `O` | 退出 Offboard |
| `Z` | 安全退出或请求降落 |

### 智能体未来适用范围

智能体的价值不应是代替一次 `W` 按键，而应是执行完整任务，例如：

```text
起飞到 1.5 m → 飞到墙面前方 → 稳定悬停 → 展开机械臂
→ 根据电机余量调整机械臂速度 → 完成清洁 → 收回 → 返回 → 降落
```

未来智能体可以负责：

- 自然语言任务解析；
- 多步骤任务排序；
- 指定距离、坐标和航向的轨迹生成；
- 飞行与机械臂动作协调；
- 电机接近饱和时减慢或暂停机械臂；
- 漂移增大时收回机械臂或终止任务；
- 自动返航、重复路径和任务日志。

PX4 始终保留底层姿态稳定、控制分配和最终安全控制权。语言模型只在接收新
任务时解析意图，不能参与 250～400 Hz 的实时姿态控制。

## 3. 推荐的未来并行架构

智能体恢复开发后，不应串联阻塞 WASD，而应采用并行入口：

```text
人工 WASD ──────────────┐
                        ├→ 统一目标管理器 → PX4 → Gazebo
自然语言/自动任务智能体 ─┘          ↑
                              安全监督器
```

建议保留三种模式：

1. **手动模式**：WASD 直接修改 PX4 位置/航向目标；
2. **辅助驾驶模式**：WASD 为主，规则程序负责限速、悬停和安全保护；
3. **自动任务模式**：自然语言或任务文件生成完整任务序列。

人工取消任务、悬停和紧急处置必须始终可用。自然语言解析延时只允许发生在
任务执行前，不能累积到每个飞行控制周期。

## 4. 已建立但暂不启用的监督智能体原型

本次讨论期间建立了第一版规则型监督原型：

- 源码：`src/drone_arm_sim/drone_arm_sim/rule_supervisor.py`
- 测试：`src/drone_arm_sim/test/test_rule_supervisor.py`
- ROS 2 入口：`rule_supervisor`
- 状态：`NORMAL / SLOW / PAUSE / RETRACT / LAND`
- 输出话题：
  - `/my_drone/supervisor/arm_speed_scale`
  - `/my_drone/supervisor/action`

它观察：

- 水平和垂直漂移；
- 机体倾角；
- 机械臂反作用力矩；
- 八路电机饱和率。

该原型具有 2 秒恢复滞回，风险升级立即生效。当前设计为
`advisory_only=true`，只发布建议，不发送电机、机械臂或 PX4 命令。

测试记录：

```text
44 passed
Gazebo 只读试运行状态：NORMAL
arm_speed_scale：1.0
arm_torque：约 0.0512 N·m
horizontal_error：0 m
vertical_error：0 m
motor_saturation_fraction：0
```

此原型目前不得加入正式启动脚本，也不得据此宣称“全智能体控制已经完成”。

## 5. 当前近期目标与验收顺序

近期只推进 WASD 正式基线：

1. 确认正式 CAD 机体与 SO101 在 Gazebo 中完整显示；
2. PX4 预飞检查通过，无 failsafe；
3. `T` 能可靠解锁并起飞到目标高度；
4. 分别验证 `W/S/A/D` 的机体系方向；
5. 验证 `R/F` 高度控制和 `Q/E` 偏航；
6. 验证松开按键后稳定悬停；
7. 验证 `L` 正常降落、落地并解除武装；
8. 至少连续完成多轮相同序列，不依赖偶然成功；
9. 记录位置误差、姿态变化、电机饱和率和 PX4 failsafe；
10. 不通过放宽安全阈值掩盖控制、分配或推力余量问题。

建议标准回归序列：

```text
T → W → D → S → A → Q → E → R → F → L
```

## 6. 未来恢复智能体开发的条件

满足以下条件后再恢复：

- WASD 起飞、移动、悬停和降落可重复通过；
- 电机编号、轴线和控制方向已验证；
- 无机械臂状态的基础飞行稳定；
- 机械臂低幅度动作有可靠飞行基线；
- 已定义统一的结构化目标格式和人工接管优先级。

恢复时的建议顺序：

1. 将 WASD 和自动任务都转换为同一种结构化位置/航向目标；
2. 先做确定性任务状态机，不使用大语言模型控制实时飞行；
3. 接入监督器的速度倍率、暂停和收回建议；
4. 增加受限的自动 LAND 请求网关；
5. 最后再增加自然语言解析、视觉目标或强化学习补偿。

## 7. 给后续 AI 的同步说明

后续 AI 接手时应遵守：

- 当前主线是 WASD，不要擅自切换为智能体自动控制；
- 不要让语言模型直接输出八路电机命令；
- 不要把监督原型自动加入启动脚本；
- 不要覆盖 7.735 kg 正式可飞基线；
- 智能体原型只作为可复用备选模块；
- 如果继续智能体工作，应先征得用户明确同意，并从统一目标接口开始。
