# my_drone 7.735 kg 正式启动说明

本文是当前正式启动入口。运行环境是默认 WSL `Ubuntu-24.04`、ROS 2 Jazzy 和本地 `/home/asus/PX4-Autopilot`。模型几何来源固定为 `E:\清洁无人机\零件`，启动时使用拆分后的正式 URDF，不使用早期虚拟八旋翼模型。

## 当前固定配置

- 整机工程质量：`7.735 kg`。
- CAD 密度估算证据：`8.567252 kg`，保留在 `my_drone_v3_cad_physical.json`，不作为当前飞行质量。
- 正式模型：`src/drone_arm_sim/urdf/my_drone_v3/my_drone_cad_formal_dynamic.urdf`。
- 飞行配置：`src/drone_arm_sim/config/my_drone_v3_cad_7p735_flight.json`。
- PX4 机型：`4026_gz_my_drone_octorotor_7p735`。
- PX4 悬停参数：`MPC_THR_HOVER=0.8737`，由静态推力表反插值得到，不是线性最大推力比例。
- 额定单电机上限：`1.2 kgf = 11.76798 N`；正式悬停解最大单电机约 `11.335426 N`。
- 首版飞行测试关闭电池压降，表示“理想 14.8 V 供电可行性测试”；接入真实电池参数前不能宣称实机等效。

## 启动 Gazebo、PX4 和 Micro XRCE-DDS

在 PowerShell 执行。默认值已经是正式模型、正式配置和 `4026`：

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "cd '/mnt/e/清洁无人机/drone_sim_ws' && HEADLESS=false ENABLE_ARM_CONTROL=true bash scripts/wsl_start_ros2_dds.sh"
```

看到以下标志才表示链路就绪：

```text
ROS2_DDS_READY arm_control=true
logs=/tmp/my_drone_ros2_dds
```

启动脚本会清理旧 PX4、Gazebo、Agent 和残留 DDS 键盘节点，启动 Micro XRCE-DDS Agent (UDP 8888)，加载正式 URDF，启动 `gz_ros2_control`，并在报告 READY 前发送一次 `retracted` 姿态保持命令。

只测试飞行、不加载机械臂控制器时：

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "cd '/mnt/e/清洁无人机/drone_sim_ws' && HEADLESS=false ENABLE_ARM_CONTROL=false bash scripts/wsl_start_ros2_dds_noarm.sh"
```

如果用 `HEADLESS=true`，另开窗口显示 Gazebo：

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "source /opt/ros/jazzy/setup.bash && gz sim -g --force-version 8"
```

## WASD 操作

启动后在第二个 PowerShell 窗口运行：

```powershell
powershell -ExecutionPolicy Bypass -File "E:\清洁无人机\drone_sim_ws\scripts\start_ros2_dds_wasd.ps1"
```

控制终端必须保持焦点：

| 按键 | 动作 |
|---|---|
| `T` | 进入 Offboard、解锁并起飞到约 1.2 m |
| `W/S` | 机头方向前进/后退 |
| `A/D` | 机体左/右移动 |
| `R/F` | 上升/下降 |
| `Q/E` | 左/右偏航 |
| `L` | 降落并自动解除武装 |
| `O` | 退出 Offboard，请求位置控制 |
| `Z` | 未解锁时安全退出；已解锁时先请求降落 |
| 连按两次 `X` | 紧急解除武装，仅限失控时使用 |

WASD 链路是：键盘 → ROS 2 `dds_wasd_control` → `px4_msgs`/Micro XRCE-DDS → PX4 → `/fmu/out/actuator_outputs` → Gazebo 直接动力插件。不要同时运行旧 `px4_wasd_control.py` 或任何 pymavlink Offboard 节点。

## 机械臂模式

完整地面动作仍可用：

```powershell
wsl.exe -d Ubuntu-24.04 -- bash -lc "cd '/mnt/e/清洁无人机/drone_sim_ws' && bash scripts/run_ros2_arm_preset.sh work_a 3"
wsl.exe -d Ubuntu-24.04 -- bash -lc "cd '/mnt/e/清洁无人机/drone_sim_ws' && bash scripts/run_ros2_arm_preset.sh work_b 3"
wsl.exe -d Ubuntu-24.04 -- bash -lc "cd '/mnt/e/清洁无人机/drone_sim_ws' && bash scripts/run_ros2_arm_preset.sh retracted 3"
```

飞行中使用 `test_ros2_dds_arm_flight_pty.py` 验证的安全动作是 `flight_work_a`、`flight_work_b` 和 `retracted`。它们约为完整工作姿态的 20%，并采用 8 秒渐进动作，以适应当前 7.735 kg 配置只有约 7.5% 理想推力余量的限制。完整 `work_a/work_b` 在 3 秒内展开会使电机饱和并造成明显漂移，当前不应作为飞行动作。

完整 `work_a` 的30秒渐进诊断可用 `ARM_FLIGHT_PROFILE=full_a` 显式触发，但最近测试仍触发饱和/failsafe；它仅用于后续推力余量和动力参数标定，不属于默认验收路径。

## 已知边界

4/5/7/8 的相反螺距是当前可悬停场景假设，CAD 平板桨叶本身不能证明螺距正负；`Q/T=0.001 m`、电机 `0.035 s` 时间常数、风阻/地效和电池内阻仍是待标定估计。补齐桨叶型号、RPM—推力—扭矩表、称重和电池数据后，应重新生成配置和 `4026` 机型。
