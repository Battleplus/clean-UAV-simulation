# 第 4～5 步：八旋翼动力学表与控制分配验收

## 当前模型边界

输入是 PX4/Gazebo 的归一化电机命令 `u∈[0,1]`。每台电机的推力由 `my_drone_v3_cad_7p735_flight.json` 中的 14.8 V 静态推力表分段插值得到，并受 `11.76798 N` 上限限制；目前没有 RPM 数据，因此 `k_f`、`C_T`、`C_Q` 和独立 RPM→推力模型保持 `null/未标定`。反扭矩使用临时 `Q/T=0.001 m`。

逐电机接口：

```python
from drone_arm_sim.gazebo_direct_motor_model import (
    motor_wrench_frd,
    per_motor_wrench_frd,
)

thrust_n, force_frd_n, torque_frd_nm = motor_wrench_frd(config, 1, 0.5)
records = per_motor_wrench_frd(config, commands)
```

`motor_wrench_frd` 返回单台电机的推力、FRD 力和 FRD 力矩；`per_motor_wrench_frd` 返回 1～8 全部记录。运行时 Gazebo 使用 `wrench_position_m`（`base_link` 原点），而 PX4 分配矩阵默认使用 `position_m`（车辆质心参考），两个参考点有意保持区分。

## 验收结果

- 7.735 kg 悬停目标：
  - 分配推力 `[10.675140, 11.222150, 10.675140, 11.335426, 10.561864, 11.222150, 10.561864, 11.335426] N`
  - 残差范数：`2.98e-14`
  - 电机饱和：无
- 人为不可实现的 `Fz=-200 N` 目标：八台电机均被识别为上限饱和，残差约 `118.47`，说明限幅诊断生效。
- 静态回归：`23 passed`。

这一步已经能对每个输入命令计算力和力矩，并能处理分配上下限；但只有在获得 RPM、桨叶手性和台架反扭矩后，才能升级为“真实电机动力学”。
