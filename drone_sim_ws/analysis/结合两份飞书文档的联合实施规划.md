# 结合两份飞书文档的联合实施规划

更新日期：2026-08-12

## 1. 规划依据

本规划综合以下两份飞书文档：

- 《仿真》：比较 Gazebo、Isaac Sim 和 AirSim，强调 UAM 必须保留多刚体耦合、动态质心、反作用力矩和接触力。
- 《基于 Gazebo 与 ROS 2/PX4 SITL 的 8 旋翼异构全驱动空中操纵系统仿真控制方案》：给出整体动力学、6×8 控制分配、PX4/Gazebo 飞行闭环、ros2_control 机械臂闭环和 Micro XRCE-DDS 通信架构。

结合本项目实测，正式路线冻结为：

```text
CAD/URDF/SDF 多刚体真值层
        │
        ├── Gazebo：机身、8 旋翼、SO101、接触与传感器
        │
        ├── PX4 SITL：EKF2、位置/速度/姿态/角速度反馈环
        │       └── 6×8 受约束控制分配 → 8 路电机
        │
        ├── ros2_control：SO101 关节轨迹、限位、夹爪
        │
        └── UAM 补偿层：动态 CoM/惯量/反作用 wrench 估计
                ├── 力补偿 → PX4 加速度/总力目标
                └── 力矩补偿 → 6×8 分配器的总 wrench 目标
```

MoveIt 2、LeRobot、视觉和 RL 均放到飞行—机械臂动力学闭环验收之后。

## 1.1 本项目的首要集成原则

本项目不是重新设计一套飞机控制器，而是在当前已经能够起飞、悬停、WASD 速度飞行、偏航和降落的 4 kg 机架基线上，增加 SO101 机械臂能力。

必须遵守以下非回归约束：

1. 保留当前 PX4 位置、速度、姿态和角速度反馈闭环，不改变其基础控制逻辑与现有 WASD 语义。
2. 保留当前机架、八旋翼动力插件、传感器、airframe 和已通过的 6×8 基础分配配置。
3. 机械臂关节控制独立运行，只通过 Gazebo 多刚体动力学自然影响机身。
4. 机械臂补偿是可选的附加前馈，不得替换 PX4 反馈控制，也不得在分配后直接改写单台电机输出。
5. 补偿关闭、异常、超时或安全门触发时，输出必须平滑归零，飞机继续使用原来的 PX4 悬停能力。
6. 每加入一项机械臂功能，都必须先重复无机械臂飞行回归；起飞、悬停、WASD、偏航、降落任一项恶化即撤回该项改动。
7. 机械臂动作的默认策略是“飞机悬停目标不变，机械臂慢速运动，补偿器只抵消机械臂新增扰动”，不能同时改变飞机的速度/位置目标。

对应的软件边界为：

```text
现有 PX4 飞行基线（保持不动）
  ├── WASD/悬停目标 → PX4 原级联控制器 → 基础 6D wrench
  └── 传感器/EKF/安全状态机

新增机械臂能力（可独立关闭）
  ├── SO101 关节/夹爪轨迹 → ros2_control/Gazebo joint
  ├── 动态 CoM/惯量/反作用 wrench 估计
  └── 有界补偿 wrench ───────────────┐
                                      v
基础 wrench + 补偿 wrench → 一次受约束 6×8 分配 → 8 电机
```

因此，机械臂功能不再通过修改 WASD 目标或重置悬停目标来“帮助稳定”；悬停仍由原飞行闭环负责，机械臂层只提供动作调度、安全门和经过 A/B 验收的扰动补偿。

## 2. 对飞书方案的工程修正

### 2.1 保留的结论

1. Gazebo + ROS 2 + PX4 是当前传统控制和多体动力学验证的正确主栈。
2. 飞行和机械臂使用两条控制总线，但在 Gazebo 物理层保持真实耦合。
3. 8 个倾斜旋翼必须用真实位置、推力轴和旋向建立 6×8 控制效能矩阵。
4. 机械臂运动必须显式估计动态 CoM、惯量变化和反作用 wrench，不能只靠调大 PX4 PID。
5. `/clock`、DDS 数据年龄和控制输出连续性是联合仿真的验收对象，不只是启动条件。

### 2.2 不能直接照抄的部分

1. 当前环境是 Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Sim，不再额外安装 Humble/RoboStack/Conda 全家桶，避免重复依赖污染。
2. 6×8 矩阵 `rank=6` 只证明几何上能够生成六维 wrench，不代表 PX4 会自动知道机械臂扰动。必须先生成正确的补偿 wrench，再交给分配器。
3. `control_allocator` 负责分配已给定的控制目标；它不会凭空计算机械臂动态质心，也不能保证在电机饱和时维持六自由度控制。
4. “100 Hz 零空间优化即可完全抵消机械臂”不能作为验收结论。频率、延迟、推力余量、条件数和模型误差都必须实测。
5. 飞书中的示例坐标、airframe 编号、`CA_ROTOR*_KM` 和 Xacro 安装位姿只是示例，不能覆盖 `E:\清洁无人机\零件` 的正式 CAD 数据。
6. MoveIt 2/LeRobot 解决轨迹与策略生成，不解决机身动力学稳定问题；现阶段不能用它们替代补偿控制器。

## 3. 当前项目事实与双基线

### 3.1 4 kg 算法开发基线

- 用于 WASD、悬停、按键 6 和补偿算法的可重复开发。
- 补偿关闭、完整伸展/收回各 90 s 的 Headless 测试已通过：水平漂移约 0.108 m，高度跨度约 0.199 m，最大倾角约 1.345°，无电机饱和。
- 简单静态 CoM 前馈 `gain=0.5` 的成对 A/B 使水平漂移和最大倾角恶化，因此已否决，默认必须关闭。
- 当前按键 6 每程约 30 s，比已通过的 90 s 基线快约 3 倍，不能把两者视为同一测试。

### 3.2 7.735 kg 正式物理基线

- 保留 `f9426ef` 和 `baseline-7p735-flyable`，不得覆盖或删除。
- 当前最大推力和倾斜推力轴下，垂向推重比约 1.075，完整机械臂动作时推力余量很小。
- 即使分配矩阵满秩，饱和后也无法实现期望 wrench；补偿算法不能创造额外推力。
- 4 kg 补偿增益不能直接迁移到 7.735 kg。

## 4. 分阶段实施计划

### 阶段 0：恢复单一、可重复的启动链

任务：

1. 固定 Jazzy/Gazebo/PX4/Micro XRCE-DDS 的唯一安装和启动脚本。
2. Headless Gazebo server 与 GUI client 分离；渲染异常不得拖死传感器或 DDS。
3. 启动顺序固定为 Gazebo 模型落稳 → PX4 → DDS Agent → EKF 就绪 → 解锁/起飞 → 机械臂控制。
4. 对 PX4、Gazebo、DDS 和控制节点增加 PID 文件、心跳、数据年龄和退出清理。

验收：连续 5 次干净启动；WASD 起飞、悬停、前后左右、偏航、降落均正常；无残留旧进程和旧窗口。

这一阶段同时冻结飞行基线文件清单和校验值。后续机械臂分支不得修改这些文件；确需修改公共启动脚本时，必须证明补偿关闭状态与冻结基线行为一致。

### 阶段 1：冻结几何、质量和控制效能

任务：

1. 以 `E:\清洁无人机\零件` 总装为唯一几何来源。
2. 冻结 1～8 号电机的 CAD 轴心、推力轴正方向、CW/CCW、推式/拉式和 PX4 输出映射。
3. 确认 4、5、7、8 的反向螺距桨事实；不能仅按旋向推断推力方向。
4. 生成并版本化 6×8 矩阵，记录 rank、奇异值、条件数、悬停解和各电机余量。
5. 质量分两套：4 kg 试验配置与 7.735 kg 正式配置；惯量、CoM 和临时估计必须标注来源。

验收：电机参数证据表完整；矩阵静态单元测试通过；悬停解无负推力、无越界，且明确剩余推力裕度。

### 阶段 2：恢复无补偿的飞行与机械臂基准曲线

任务：

1. 关闭所有机械臂补偿、DOB 和实验电机偏置。
2. 以固定 seed 重复 90 s 伸展/90 s 收回至少 3 次。
3. 分别记录机械臂不动、单关节、慢速全臂、30 s 动作和按键 6。
4. 记录位置、速度、姿态、角速度、8 路电机推力、饱和率、DDS 数据年龄和安全门状态。
5. 每轮机械臂测试前后各执行一次原始 WASD/悬停回归，确认机械臂节点存在但不动作时不会改变飞机控制。

验收：先复现 4 kg 已通过结果；若 GUI 失败而 Headless 通过，归类为运行链故障，不归类为控制算法失败。

### 阶段 3：建立高频可变惯性估计器，只观察不补偿

任务：

1. 由 `q/q_dot/q_ddot` 和每个刚体质量属性，在 `base_link/FLU` 中以 100 Hz 计算整体 `r_c(q)`、完整 `I_c(q)` 及其变化率。
2. 分离三个扰动来源：静态重力矩 `r_c × Mg`、连杆加减速反作用力、角动量/惯量变化反作用力矩。
3. 对差分量使用带限微分和时间戳，不直接放大 Gazebo 噪声。
4. 每个消息携带 frame、单位、时间戳、置信度、限幅和 freshness。
5. 与 Gazebo 关节力、基座角动量变化和离线多体计算做符号与量纲交叉验证。

验收：所有坐标转换 FLU↔FRD↔NED 单元测试通过；估计输出连续、无跳变，静态项与动态项可分离。此阶段不得影响电机输出。

### 阶段 4：单通道前馈 A/B

按照以下顺序逐项测试，不得混合调参：

1. 仅平动力补偿：`a_ff = -F_dis/M`，注入 PX4 外环加速度/总力路径。
2. 仅静态重力矩补偿：`-tau_g`，注入分配器前的总力矩目标。
3. 仅动态反作用力矩补偿：`-tau_dyn`，注入同一总 wrench。

共同约束：

- 初始增益从 0.05～0.10 开始；不得从 0.5 继续盲调。
- 数据超过 100 ms、DDS 中断、PX4 非稳定悬停或电机余量不足时，补偿平滑退回 0。
- 补偿量与 PX4 基础目标先合成为一个 6D wrench，再做一次受约束 6×8 分配；禁止在分配后直接给单个电机叠加偏置。
- 分配器包含推力上下限、变化率、优先级和抗饱和；优先保持总垂向力及滚转/俯仰。

验收：相同 seed、轨迹和初始状态的 off/on 成对 A/B；水平漂移和最大倾角都不得恶化，高度跨度恶化不超过 0.02 m，无饱和、无 failsafe。

### 阶段 5：组合补偿与速度递进

任务：

1. 只有阶段 4 通过的单通道才允许组合。
2. 动作速度依次为每程 90 s → 60 s → 30 s → 人工按键 6。
3. 每个约 5 mm Cartesian 路点检查速度、倾角、漂移、电机余量和 DDS freshness；超限时暂停后续路点并平滑收回。
4. 引入关节轨迹的 jerk 限制，使起止速度和加速度为零，减少不可补偿的高频冲击。

验收：相对无补偿基线，水平漂移与 RMS 倾角至少降低 20%，且所有安全门通过。

### 阶段 6：残差扰动观测器

任务：

1. 模型前馈通过后，DOB 先只记录“机体实测响应－模型预测响应”。
2. 只补偿模型未覆盖的低频残差，建议起始低通带宽 3～5 Hz，并设置独立增益与限幅。
3. 防止 DOB 与模型前馈重复补偿同一扰动。

验收：被动记录 → DOB off/on Headless 成对 A/B → GUI 人工验收。未通过前默认关闭。

### 阶段 7：迁移到 7.735 kg 正式配置

任务：

1. 重新计算质量归一化、惯量、悬停解、分配权重和全部安全限幅。
2. 先机械臂收回飞行，再做极慢、小幅动作；逐级扩大，不能直接运行 30 s 完整伸展。
3. 若电机长期接近饱和，优先修正物理方案：减重、提高单电机推力、减小旋翼倾角损失或限制机械臂动作包络，而不是继续增大补偿增益。

验收：正式质量下无机械臂动作稳定；收回与慢速工作状态均无饱和、无 failsafe；完整动作是否允许由实测推力余量决定。

### 阶段 8：轨迹规划、视觉与具身智能

前置条件：阶段 7 通过。

1. 接入 MoveIt 2 做限位、碰撞和无碰轨迹，不改写底层飞行补偿链。
2. 再接入手眼相机、目标物体和接触力测试。
3. LeRobot/RL 只输出末端或关节目标；安全过滤、飞行状态机和补偿器仍由确定性控制层负责。
4. 最后再做 PX4/Gazebo-in-the-loop RL；现有离线 RL 回归不能等同于闭环完成。

## 5. 控制与通信接口冻结

```text
PX4 → ROS 2:
  vehicle_odometry / vehicle_status / actuator_outputs / failsafe 状态

ROS 2 → PX4:
  trajectory_setpoint（位置/速度/加速度分量）
  offboard_control_mode
  vehicle_command
  补偿后的 6D wrench（项目自定义受约束分配路径）

机械臂:
  joint_states + 带时间戳轨迹
  关节限位、速度、加速度、jerk、夹爪状态

监控:
  dynamic_com / dynamic_inertia / estimated_wrench
  allocator_residual / motor_margin / saturation
  dds_age / gazebo_clock_age / compensation_health
```

所有接口只允许一个发布者拥有最终控制权；人工 WASD、悬停键和机械臂动作节点通过统一状态机仲裁，避免互相覆盖目标速度或保持最后一次电机输出。

## 6. 当前立即执行顺序

1. 关闭当前未验收的 25% 混合补偿，恢复 4 kg 无补偿可重复基线。
2. 将按键 6 的空中轨迹先恢复为每程 90 s，并补齐逐路点安全门。
3. 完成 100 Hz 可变 CoM/惯量/wrench 估计器的只读验证。
4. 将当前“电机后叠加偏置”替换为“总 wrench 合成后统一 6×8 受约束分配”。
5. 从三个单通道 0.05～0.10 增益做成对 A/B，只有量化改善项才保留。
6. 4 kg 通过后再迁移到 7.735 kg；若推力余量不足，明确判为物理能力瓶颈。

## 7. 最终完成判据

- 飞行：起飞、悬停、WASD 速度控制、偏航、降落可重复。
- 机械臂：收回、工作姿态、伸直—保持—原路收回、夹爪动作可重复。
- 联合：机械臂动作期间无 DDS 中断、无电机饱和、无 failsafe，漂移与倾角满足量化门限。
- 模型：CAD 几何、质量、惯量、推力与旋向来源可追溯；临时参数明确标注。
- 控制：所有补偿都有 off/on 成对 A/B 证据；默认配置只包含已通过项。
- 高层：MoveIt 2、视觉或 RL 的加入不得破坏底层确定性安全链。
- 非回归：机械臂关闭时，飞机的悬停、WASD 速度响应、偏航和降落必须与当前 4 kg 冻结基线一致；机械臂开启但静止时也必须满足同一要求。
